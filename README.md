# 労務稼働予定（山積み）アプリ — 金子建設工業

スマホのブラウザで開く、土工・鳶工の労務稼働予定（山積み）入力アプリです。ログインなし、**URL＋合言葉**で見る・直すことができます。

- このリポジトリ（公開）には**プログラムだけ**があり、現場名などのデータは入っていません。
- データは非公開リポジトリ `kaneko-roumu-data` の `data/roumu.json` にあり、ブラウザが GitHub API で直接読み書きします（サーバーなし）。
- そのための GitHub トークン（`kaneko-roumu-data` の Contents 読み書きだけに絞った fine-grained PAT）は、**合言葉で暗号化した形でだけ** `config.js` に入っています（PBKDF2-SHA256 60万回 → AES-256-GCM）。
- `?demo=1` を付けると、架空の現場名の体験用データで動かせます（保存されません）。

## 画面
| 画面 | 内容 |
|---|---|
| 現場 | 土工／鳶工タブ、新築・改修ごとの現場一覧（区分・工事名・部・所長・職長・工期・月数・今月の人数）。追加・編集・削除 |
| 現場 → 月別 | 年度タブ（5カ年）、月ごとの 人/日 を −／＋ で入力。日別の年度は 人工・稼働日 も表示 |
| 現場 → 日別 | 月カレンダー。「1日ずつ」（日曜・祝日も入力可）、「期間でまとめて」（休みの日も含めるか選べる）、「複数えらぶ」（タップ・曜日・隔日で選んで同じ人数）。現場ごとの休み／出勤の上書き |
| 5カ年 | 現場×月の表（年度タブ・横スクロール）、新築計・改修計・合計・月間稼働予測・余力 |
| 集計 | 月ごと／日ごと切替、土工・鳶工のグラフ、稼働予測（カレンダー／×22日 Excel方式）比較、売上見込み、CSV出力 |
| カレンダー | 会社カレンダー（日曜・祝日・年末年始・GW・お盆・臨時休み）、土曜閉所の設定、月ごとの稼働日数、日別年度の切り替え、目標人数 |
| 設定 | 単価（土工・鳶工 円/人工）、名前、最新読み込み、CSV、合言葉を忘れる |

## 工事一部・工事二部（社内の部）
- 各現場に `division`（"1"＝工事一部、"2"＝工事二部）。未設定なら 新築→一部、改修→二部。編集画面で変更できます。
- 集計の「月ごと（通期）」で 1年／3カ年／5カ年 を切り替え、「鳶工 一部・鳶工 二部・土工 一部・土工 二部」をチェックすると、その組の山積みを積み上げ棒グラフ＋合計線で通しで表示します（職種が1つだけのときは目標線も）。チェックと期間はスマホごとに記憶。CSVもチェックした組だけを出力します。

## 竣工の現場
- 区分が「竣」の現場だけを竣工として扱います（工期の終わりでは判断しません）。
- 一覧・5カ年・集計・CSVでは竣工を隠し、合計・余力からも除きます。「竣工も表示」をオンにすると表示して合計にも含めます（スマホごとに記憶）。
- 現場の画面・編集画面の「竣工にする」で区分を「竣」に（元の区分を `prevKubun` に保存）、「竣工を解除」で元の区分（不明なら「現」）に戻します。人数のデータは消えません。

## ルール（1カ年＝日別、5カ年＝月別）
- 日別の年度（`settings.dailyFY`）の月は**日別が元データ**。月の値＝人工合計÷その現場の稼働日数。
- その月に月の値を入れると、`round(値×稼働日)` 人工を稼働日に整数で均等に割り振る（最大剰余法）。手入力した日がある月は確認してから上書き。
- それ以外の年度は月の値をそのまま保存。日別の年度を進めると、出ていく年度は月平均で固定し、入ってくる年度は月の値を日に割り振る。
- 祝日：内閣府「国民の祝日」CSV（2026・2027年）。2028〜2031年は祝日法の規則と春分・秋分の近似式による見込み（`holidays.json`）。

## 休みの日の入力と稼働日数（v1.1）
- 日曜・祝日・会社の休み・現場の休みの日にも人数を入れられます（カレンダーでは灰色＝休み、オレンジ＝休みの日に出勤）。入れた人工はそのまま月の人工・集計・CSVに入ります。
- **月の稼働日数＝その現場の稼働日（会社カレンダー＋現場の曜日設定＋日ごとの休み/出勤）＋休みの日なのに人数が入っている日**。月の値（人/日）＝人工合計÷この稼働日数。
  - 例：稼働日23日に各2人（46人工）＋日曜1日に4人 → 50人工÷24日＝2.08人/日。
  - 休みの日に入れても平均が不自然に上がらないように、入れた日は「その現場が動いた日」として数えます。
- 月の値を入れて日に割り振るときは、その現場の稼働日だけに配ります（休みの日には配りません。休みの日の手入力はその月を上書きしたときだけ消えるので、上書き前に確認が出ます）。

## 現場の曜日設定（定休日・日曜稼働）
- 現場の情報を直す画面の「この現場の曜日」で、曜日ごとに 通常／休み／出勤 を選べます（`site.week`、例 `{"3":"off","0":"work"}`＝水曜定休・日曜稼働）。
- 「休み」はその曜日を休みに、「出勤」は日曜・土曜閉所の日を稼働日にします。祝日・会社の休み（年末年始など）は曜日設定では変わりません（日別画面でその日だけ「出勤にする」）。
- 稼働日数・月の値→日の割り振り・5カ年の人工（日別でない年度は 平均×その現場の稼働日）に反映します。

## 複数えらぶ（一括入力）
1. 日別画面で「複数えらぶ」。
2. 日にちをタップで選ぶ／外す。または期間（◯日～◯日）を選んで、曜日ボタン（月・水・金 など）・「隔日」（期間の初日から1日おき）・「稼働日」・「全日」でまとめて選ぶ。
3. 人数を入れて「選んだ◯日を◯人にする」。0人にすると消せます。

## 単価・売上見込み
- 設定画面で 土工・鳶工 の単価（円/人工）を入れます（`settings.unitPrice`、初期値は未設定＝null）。現場ごとに違う単価は現場の情報で上書き（`site.unitPrice`）。
- 売上見込み＝人工×単価。人工は集計の「稼働予測」と同じ方式（カレンダー／×22日）。集計（選んだ組・1年/3カ年/5カ年）、現場の画面（年度・5カ年合計）、月別CSV（現場ごとの 人工・単価・売上、職種・組・選択合計の月別売上）に出ます。
- 単価が無いときは 0円 と出さず「単価未設定」と表示し、設定へのボタンを出します。

## データの形（schema）
- `kaneko-roumu/1.1`：1 に `settings.unitPrice`・`site.week`・`site.unitPrice` を足しただけ（全部なくても動く。古いデータはそのまま読めます）。

## 鍵（トークン）の設定・合言葉の変更
1. fine-grained PAT を作る（Repository access: Only select repositories → `kaneko-roumu-data`、Permissions: Contents = Read and write のみ）。
2. `node tools/encrypt-token.mjs <トークンのファイル> <合言葉のファイル>` を実行（または `setup.html` をブラウザで開く。計算はブラウザ内だけ）。
3. 更新された `config.js` をコミット。合言葉を変えるときも同じ手順。合言葉が漏れたら、トークンも作り直して古いものを削除してください（暗号文は公開されているため）。

同時に保存した場合は、最新を取り直して自分の変更を上に重ねて保存し直します（別の場所の変更は両方残ります。同じマスはあとから保存した方）。

## 出来高管理（`dekidaka.html`）
請書ごとの月次請求・人工を入れて、Excel「出来高管理システム」と同じ計算（出来高集計・会議サマリー）を出す画面です。労務の画面の下の「💴 出来高」からも開けます。

### 合言葉は労務とは別（2つ）
| 合言葉 | 使う人 | できること |
|---|---|---|
| 入力用 | 番頭さん | 請書 → 締め月 → 請求額（税抜）・人工・備考を入れて保存。見られる範囲は下の「入力用の範囲」で決まる |
| 閲覧用 | 幹部 | すべて見る（累計・出来高・目標差・達成率・会議サマリー）、だれの入力でも訂正、請書マスタ・合算グループ・目標単価の編集、CSV |

労務の合言葉では出来高は開けません（鍵が別）。

### 入れ方（スマホ）
1. 「入力」で請書をえらぶ。
2. 締め月をえらぶ（「2026年10月分（9/21〜10/20）」のように 21日～翌20日。今日の締め月が最初に出ます。◀▶で前後）。
3. 当月請求額（税抜・円、マイナスは先頭に -）、当月投入人工、備考を入れて「保存する」→ 確認 → 保存。
   - 入力用は**空欄の項目は変わりません**（前の値のまま）。閲覧用は今の値が入った状態で開き、変えた項目だけ保存。「空にする」で消せます。
4. 保存した内容はその場で表示し、**そのスマホにだけ**控えとして残ります（「その他」で見られる・消せる）。

### 計算（Excel の式どおり）
- 月次シート：累計請求＝当月請求の積み上げ、累計人工＝当月人工の積み上げ（空欄は0）。
- 出来高集計（合算グループごと）：合算請求・合算人工、月次出来高＝IF(人工=0,空欄,請求÷人工)、目標差異＝出来高−目標、達成率＝出来高÷目標、累計請求・累計人工・累計出来高。
- 会議サマリー：請書金額、累計請求、消化率＝累計÷請書金額、累計人工、合算出来高、目標単価、差異、評価（◎ 目標以上／○ 目標の9割以上／△）。単独管理の請書は出来高まで。総請求額集計は対象外（小口）も含めた全請書の累計と構成比。
- グループ分けは Excel の式から：合算＝「出来高集計」が足している2請書ずつ、単独＝サマリーの「単独出来高管理」、対象外＝出来高対象「×」。請書マスタで変えられます。
- 報告月は選べます（初期値はデータのある最新の月）。累計はその月の分まで。Excel のサマリーは全期間の累計なので、最新の月を選ぶと Excel と同じになります。
- 請書金額が空欄の請書は「未設定」（Excel では 0／0%）。

### しくみ（お金の数字を公開しない）
- データは非公開リポジトリ `kaneko-roumu-data` の `data/dekidaka/` に**暗号文だけ**で置きます。公開リポジトリ（このアプリ）には金額は入っていません（体験モード `dekidaka.html?demo=1` は架空の数字）。
  - `state.json`：取り込み済みの全データ。区分（names＝請書名、master＝請書金額・期間など、claims＝請求額、labor＝人工・備考、targets＝目標単価・グループ、notes＝コメント）ごとに暗号化。書き換えるのは閲覧用だけ（同時保存は sha で検出して取り直し・重ね直し）。
  - `entries/<日時>-<乱数>.json`：入力1回分。新しいファイルを足すだけ（上書きしない）。閲覧用が開いたときに `state.json` に取り込みます（項目ごとに新しい方が勝つ）。
- 暗号：役割ごとに ECDH P-256 の鍵ペア。公開鍵は `config.js`、秘密鍵と GitHub トークンは各合言葉で暗号化（PBKDF2-SHA256 60万回 → AES-256-GCM）して `config.js` に。データ本体はランダムな AES-256-GCM の鍵で暗号化し、その鍵を受取人（閲覧用、範囲によっては入力用）の公開鍵で包みます（ECDH-ES＋HKDF-SHA256）。受取人でない役割は、トークンを持っていても中身を読めません。
- **入力用の範囲**（`config.js` の `dekidaka.inputScope`）：
  - `0` 入力だけ（過去の入力・結果は読めない。請書名だけ）
  - `1` 請書金額・累計請求・消化率まで（names・master・claims）
  - `2` すべて（＋人工・備考・目標単価・会議サマリー）
  - 変え方：`node tools/dekidaka-admin.mjs scope 1` → `config.js` をコミット → `node tools/dekidaka-admin.mjs rekey <閲覧用合言葉のファイル> commit`（`state.json` を新しい範囲で暗号化し直す）。範囲を**狭める**ときは、前に読めたものは入力用の鍵で読めたまま（ファイルの履歴）なので、本当に止めたいときは `keys --force` で鍵を作り直し、`rekey` してください。
- 管理コマンド：`tools/dekidaka-admin.mjs`（keys／scope／migrate／rekey／check）。合言葉・トークンはファイルで渡し、画面に出しません。

### 限界（知っておくこと）
- トークン（どの合言葉でも復号できる GitHub の書き込み鍵）を持つ人は、`data/` のファイルを**消したり壊したり**できます（読めはしない）。git の履歴に全部残るので、戻すことはできます。役割ごとに別のトークンにすると、さらに分けられます（今は労務と同じトークン）。
- 入力用のトークンは労務の `roumu.json`（人数の予定。金額なし）も読めます。
- 合言葉はスマホの中（ブラウザの保存領域）に覚えます。共用スマホでは「合言葉を忘れる」を。
- 入力用が送った内容の控えはそのスマホに平文で残ります（消せます）。
- 閲覧用の秘密鍵が漏れたら（＝閲覧用の合言葉が漏れたら）、`keys --force` で鍵を作り直して `rekey`、トークンも作り直してください。
