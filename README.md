# 労務稼働予定（山積み）アプリ — 金子建設工業

スマホのブラウザで開く、土工・鳶工の労務稼働予定（山積み）入力アプリです。ログインなし、**URL＋合言葉**で見る・直すことができます。

- このリポジトリ（公開）には**プログラムだけ**があり、現場名などのデータは入っていません。
- データは非公開リポジトリ `kaneko-roumu-data` の `data/roumu.json` にあり、ブラウザが GitHub API で直接読み書きします（サーバーなし）。
- そのための GitHub トークン（`kaneko-roumu-data` の Contents 読み書きだけに絞った fine-grained PAT）は、**合言葉で暗号化した形でだけ** `config.js` に入っています（PBKDF2-SHA256 60万回 → AES-256-GCM）。
- `?demo=1` を付けると、架空の現場名の体験用データで動かせます（保存されません）。

## 画面
| 画面 | 内容 |
|---|---|
| 現場 | 土工／鳶工タブ、新築・改修ごとの現場一覧（区分・工事名・部・所長・職長・工期・月数・今月の人数）。追加・編集・削除 |
| 現場 → 月別 | 年度タブ（5カ年）、月ごとの 人/日 を −／＋ で入力。日別の年度は 人工・稼働日 も表示 |
| 現場 → 日別 | 月カレンダー。日をタップして −／＋、「期間でまとめて」で この期間を◯人。現場ごとの休み／出勤の上書き |
| 5カ年 | 現場×月の表（年度タブ・横スクロール）、新築計・改修計・合計・月間稼働予測・余力 |
| 集計 | 月ごと／日ごと切替、土工・鳶工のグラフ、稼働予測（カレンダー／×22日 Excel方式）比較、CSV出力 |
| カレンダー | 会社カレンダー（日曜・祝日・年末年始・GW・お盆・臨時休み）、土曜閉所の設定、月ごとの稼働日数、日別年度の切り替え、目標人数 |
| 設定 | 名前、最新読み込み、CSV、合言葉を忘れる |

## 竣工の現場
- 区分が「竣」の現場だけを竣工として扱います（工期の終わりでは判断しません）。
- 一覧・5カ年・集計・CSVでは竣工を隠し、合計・余力からも除きます。「竣工も表示」をオンにすると表示して合計にも含めます（スマホごとに記憶）。
- 現場の画面・編集画面の「竣工にする」で区分を「竣」に（元の区分を `prevKubun` に保存）、「竣工を解除」で元の区分（不明なら「現」）に戻します。人数のデータは消えません。

## ルール（1カ年＝日別、5カ年＝月別）
- 日別の年度（`settings.dailyFY`）の月は**日別が元データ**。月の値＝人工合計÷その現場の稼働日数。
- その月に月の値を入れると、`round(値×稼働日)` 人工を稼働日に整数で均等に割り振る（最大剰余法）。手入力した日がある月は確認してから上書き。
- それ以外の年度は月の値をそのまま保存。日別の年度を進めると、出ていく年度は月平均で固定し、入ってくる年度は月の値を日に割り振る。
- 祝日：内閣府「国民の祝日」CSV（2026・2027年）。2028〜2031年は祝日法の規則と春分・秋分の近似式による見込み（`holidays.json`）。

## 鍵（トークン）の設定・合言葉の変更
1. fine-grained PAT を作る（Repository access: Only select repositories → `kaneko-roumu-data`、Permissions: Contents = Read and write のみ）。
2. `node tools/encrypt-token.mjs <トークンのファイル> <合言葉のファイル>` を実行（または `setup.html` をブラウザで開く。計算はブラウザ内だけ）。
3. 更新された `config.js` をコミット。合言葉を変えるときも同じ手順。合言葉が漏れたら、トークンも作り直して古いものを削除してください（暗号文は公開されているため）。

同時に保存した場合は、最新を取り直して自分の変更を上に重ねて保存し直します（別の場所の変更は両方残ります。同じマスはあとから保存した方）。
